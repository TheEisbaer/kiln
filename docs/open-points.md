# Open points

Points the decisions do not settle yet, listed by the card that has to settle them. They come from tracing one card through the POC outcomes twice on 2026-11-16, step by step, asking at each step what goes in, what comes out and what the next run starts with.

The spec for a card settles the points listed for it and removes them here in the same pull request. A point that turns out to be a real trade-off goes to the developer as a question and becomes an ADR. A spec session that meets a new gap adds it here.

## Questions for the developer, each before its card

- **Network for research** (the spec-stage card): which hosts a run may reach, and whether a spec run may read the web for its research (ADR 0009, ADR 0017).
- **Actions under "needs you"** (the review-loop card): what the developer can do with such a card besides dropping it, and what the card's two facts become afterwards (ADR 0054). Evidence from card 2: all three reviews had findings, and every fix held. Each fresh reviewer found something the last had not: a container left by a failed start, a network left on a cancelled context, a removal that cannot be repeated, and once a real hole in the seal. The third review brought the card to the developer for a fix of a few lines. The question should cover an action "fix this one finding and check only the fix", next to dropping the card.
- **Updates beyond the core** (the automatic-update card): who rebuilds and restarts the proxy and the run image after a merge (ADR 0034, ADR 0039); what the old core may still do after it has copied the store (ADR 0036); whether an unreachable Git host makes an update count as failed.

## Settled in the spec of the card that first needs them

- **Runs:** which commit a run starts from and when the card branch is made (ADR 0010); how the merged Claude Code configuration is laid over a card branch (ADR 0025); the base of "what the card changed" (ADR 0015); how a finished run is told from a failed one when its result is missing or the engine killed it for memory (ADR 0016). Also: whether the store is written or the work is saved first when a run finishes, so that no stage starts on unsaved work after a crash (ADR 0013, ADR 0035); a restart of the core between the steps of starting a run, which must not use up the retry, and networks left behind (ADR 0041); where stage documents and session records are kept and for how long (ADR 0032, ADR 0053); what happens to changes a spec or review run made to its working tree; who enforces the advisor's "at most twice" (ADR 0030).
- **Spec stage:** rejecting a spec with reasons, and answering its questions (ADR 0021, ADR 0053); the fields of a card, and the lines of a spec that the core reads (ADR 0030, ADR 0051). How the developer changes the proposed model at approval.
- **Review loop:** what a send-back round and the next reviewer receive; whether a killed run's partial work is the saved state its retry starts from (ADR 0013, ADR 0016). What implement receives after a failed check on the host, and how the core gets that output. How a run reports that the spec cannot be built as written (ADR 0012).
- **Failures:** how a pause ends and what happens to runs in flight; a credential that expires while the core is down pauses the instance and does not use up a card's retry (ADR 0016, ADR 0040). A run in flight across an update that changes the pinned Claude Code, whose output the new core was not tested with (ADR 0039); event numbers after a copy of the store is put back (ADR 0036, ADR 0044).
- **Publishing:** who writes commit messages and the pull request's title and text (ADR 0020, ADR 0028), whose format is settled (the standards card, below); failures of steps that are not runs, such as a push; where the app's key lives; what the one switch does to pull requests that already have automatic merging on (ADR 0006); removing a card branch after the merge. The host can fail to fire automatic merging: on 2026-11-16, during an incident on the host, a pull request stood with automatic merging on and every requirement met, and did not merge. The core should notice such a pull request on a tick and ask the host to merge it directly, the path ADR 0049 already has.
- **Checks:** how CPU time per check run is recorded on hosted runners (ADR 0031). The "no C code" step (ADR 0037) lets through a package made only of C that nothing imports, and a dependency that falls back to a stub without C; rejecting cgo files and packages with no Go files left would close both.

## Notes for later cards

- **The run card.** Claude Code 2.1.325, read on 2026-11-16: headless runs start in manual permission mode unless a mode is set; a mode without the repo's own configuration is announced as the future default for headless runs, so the run command has to say what it wants (ADR 0025); a run that asks for a blocked model now warns and continues on another, so the core checks the model in the first output event (ADR 0030); a resumed run reports the cost of the whole conversation (ADR 0029, ADR 0053). Every card that changes the pinned version reads the changelog between the two versions. A run's container drops all capabilities and sets `no-new-privileges` (card 3, ADR 0041). With `NET_RAW` a run sends raw frames past its own interface's settings, which is how the second review of card 2 reached the engine's virtual machine over IPv6 link-local; the run network now closes that path, and the seal's test runs its probe with the default capabilities so that it proves the network alone. A replaced proxy is no longer attached to the run networks of runs in flight; this card attaches it again when it follows a run.
- **The push card** (ADR 0040). It removes the proxy's start from the environment (`KILN_PROXY_CREDENTIAL`) in the same pull request, so that two ways never exist side by side. Renewing the credential replaces the proxy (card 3), which leaves the run networks of runs in flight. Linux accepts a packet for any of the proxy's addresses on any network it is attached to, so the push port must refuse runs by itself and cannot rely on the network it listens on.
- **The standards card.** Three of card 2's four findings were of one kind, clean-up and repeating a step on code that drives the engine. Candidate for a written standard, so that implement has it before it writes code (ADR 0015, rule 3): a function that creates or removes something on the engine leaves nothing behind when it fails, is safe to repeat (ADR 0035), and a test shows both. Also decided by the developer on 2026-11-17: commit messages and pull request titles in Kiln's repo follow Conventional Commits (`type(scope): summary`, the scope optional), from card 3 on. With squash merging the pull request's title becomes the commit on `main`, so the rule covers both. It settles the format part of "who writes commit messages and the pull request's title and text" (ADR 0020, ADR 0028); who writes them stays open. It belongs with the written standards once they exist, and a format a tool can check is a check, not review (ADR 0015, rule 4).
- **The MVP.** Kiln's layer needs a few things from a toolchain image, namely `curl`, `sha256sum`, `useradd`, `sh` and a free uid 1000.
- **The MVP card that rebuilds placing and collecting for Kubernetes** (ADR 0038). The developer asked on 2026-11-17 for a container that holds the instance's copy of the repo in a volume, so that nothing of a working tree touches the host's disk. For the POC the save's unpacking moved into a throwaway container instead (card 4). A volume that holds the copy is worth weighing at the MVP, with where saved and unpublished work is kept safe and how that container reaches the Git host.
- **The first UI card.** Modern Web Guidance, skills for coding agents on current web platform practice (Apache-2.0, stewarded by browser vendors and MDN), is worth trying. Runs are sealed, so it has to be in the repo or the run image, as part of the repo's Claude Code configuration, which is a protected place.
- **The visual design session.** Candidates for a short written standard for the UI: answer within about 400 ms, fewer choices, larger targets, familiar patterns, and less animation for what is used all day.
- **The CLAUDE.md card.** The check command comes first. A sentence that tells the agent it owns the codebase is an experiment to measure against send-backs, not a default.
